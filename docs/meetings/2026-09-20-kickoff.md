## Monday's call, 12:30–1:00

Thirty minutes. Pick three, decide who asks each, and one person takes notes for Emily.

1. **Harbor.** Every built-in Harbor agent is a coding agent, so we'd write a small custom
   agent that calls each model's chat API directly, and run the conversation as checkpointed
   next-turn tasks first, then as one live multi-step task per session. Does that fit? And is
   there a reason for Harbor we should design around — reviewer familiarity, reuse as an RL
   environment, lab standard?
2. **Memory across sessions.** Consumer assistants carry memory between chats; an API call
   doesn't. Which is the primary condition: full prior history, a summary, or nothing?
3. **The user.** An authored script with a few branches for the first conversation, a live
   simulated user later?
4. **Judge and budget.** Which judge model, a second judge from another family, who holds
   API keys, what we can spend on the Oct 8 runs.
5. **Safety gates.** Cap the score, stop the conversation, or subtract?
6. **Agreement.** What standard should the judge meet against human raters?

Questions 1, 2 and 4 are the ones the build can't proceed without.
